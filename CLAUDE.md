## Начало работы

1. `git pull --rebase`.
2. Открытые issues: `gh issue list --state open`. Метки: `bug` + `S1…S4` — ошибки от Codex,
   `codex` — задания на проверку.
3. Свежие отчёты Codex — `reports/<run>.md`, артефакты — `reports/_artifacts/<run>/`, сценарии

## Устройство (кратко)

- Корень репозитория — сам пакет расширения (`blender_manifest.toml` в корне).
- Генераторы: `nodes_builder.py` (хвойные; там же помощник `NB`), `broadleaf_builder.py` (лиственные
  и свободные кусты), `hedge_builder.py` (стриженые кусты). Группы нод строятся из Python.
- Атласы: `twig_baker.py`, `broadleaf_twig.py`, `birch_twig.py` → `textures/*.png` (2048, по 3 карты на вид).
  Маска: R — AO, G — лист, B — толщина, A — номер листа.
- Материалы — `materials.py`, пресеты — `presets.py`, операторы — `operators.py`, панель — `panel.py`.
- **API для скриптов и MCP — `api.py`**, публикуется в `bpy.app.driver_namespace["easy_conifer_api"]`.
  Инструкция для агентов — `MCP.md`.

## Правила кода

- Blender 5.x. Входы модификатора читай и пиши **только** через `modifier_io.get_input/set_input`:
  в 5.2 `mod["Socket_N"]` не работает.
- Узел Random Value без подключённого ID берёт Index. Подавай явный константный ID (`NB.rand(..., id=)`).
- Меняешь интерфейс или устройство группы нод — подними `NODES_VERSION` соответствующего билдера.
  Меняешь материал листвы — подними `FOLIAGE_MAT_VERSION`. Старые группы и материалы переименовываются
  в «(old)», значения переносит `Rebuild Node Group`.
- Новый параметр обязательно получает умолчание и описание в `INTERFACE`. Если параметр нужен в быстрой
  панели, добавь его в `panel.py` (`QUICK*`). Если новая функция полезна агентам, отрази её в `api.py`
  и `MCP.md`.
- API (`api.py`) не ломай без нужды. Функции возвращают JSON-совместимые значения, ошибки выбрасывают как
  `ValueError` с понятным текстом. При несовместимом изменении подними `API_VERSION` и опиши его
  в `Changelog.md`.
- Бюджеты полигонов (их проверяет `tests/smoke_test.py`): стриженый куст ≤ 5 тыс., хвойные ≤ 60 тыс.,
  лиственные ≤ 150 тыс. треугольников. Если бюджет меняется, меняй его в тесте и в README в одном коммите.
- Атласы перепекай осознанно. Перепечённые PNG коммить вместе с кодом, который их изменил. Сравнение
  «до/после» клади в issue или в описание коммита. EXR и временные файлы не коммить.

## Проверка перед коммитом

Локально `bpy` доступен как модуль (`pip install bpy==5.2.*`, Python 3.13), поэтому скрипты запускаются
через `python3 -I`, а не `blender -b --python`:

```
python3 -I tests/test_api.py          # все функции API
python3 -I tests/smoke_test.py        # все пресеты и формы: без предупреждений, в бюджете
python3 -I tests/smoke_test.py --bake # + запекание маленького атласа
python3 -I tests/render_preview.py --out /tmp/ec --presets HEDGE_COTONEASTER:CUBE   # посмотреть глазами
```

Оба теста должны пройти полностью. Если изменение визуальное (листва, материал, атлас), посмотри рендеры
до и после.

## Выпуск версии

1. Обнови версию в `blender_manifest.toml`, раздел в `Changelog.md`, при необходимости `README.md`
   и `MCP.md`.
2. Коммит «Easy Conifer X.Y.Z» в `main`. Если версия исправляет issues, добавь в сообщение `Fixes #N`
   и напиши в каждом issue, что проверить.
3. Заведи issue с меткой `codex`: версия, коммит, что изменилось и план проверок (какие пресеты
   рендерить, какие сценарии MCP пройти).
4. Zip собирается штатно: `blender --command extension build --source-dir . --output-dir dist`.
   Исключения перечислены в `blender_manifest.toml` → `[build] paths_exclude_pattern`. Готовые zip
   в git не коммить, релизы делай только по просьбе пользователя.
